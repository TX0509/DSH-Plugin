# 文案与配图口径

## 去 AI 味（humanizer-zh）

先读 `humanizer-zh`，按它的 31 条检查，但**只改确实有问题的表达**：

- 删：空泛抬高（堪称/彰显/惊天反转/一针见血/史诗级/教科书级）、无信息的评价词、伪洞察（「连最会算概率的人也未必算得准」）、预示后文的起跑句（「让我们深入看看」）、客服腔、重复免责。
- 保留：事实、数字、限定（可能/据称/仅/正在/计划）、否定、归因、比较对象、作者立场与调侃。
- 用户自己写的正文：只动空话，不动立场。改动前后留一份 `article.v1.md` 方便回退。
- 卡片文案比正文更紧：一页一件事，标题 8 字内，删掉「本文将/我们可以看到」。

## 用户已明确的偏好（重要）

1. **不要模糊配图**：原图分辨率必须大于显示尺寸；视频截帧（720p）不用作大幅图；宁可换图或缩小，不要硬放大。
2. **外文推文做中文译文版**：按用户给的参考样式排（头像 + 认证标 + 账号 + 「由作者翻译自英语」+ 中文正文 + 时间/互动量），不要直接贴英文截图；译文卡要注明「按原帖样式重排」。
3. **成图上不要工具品牌页脚**：网页不出现 `歸藏 Page · Built with constrained HTML`；卡片不写「guizang」。
4. **成图上不写比例/尺寸**：不写 `21:9`、`2100×900`、`1:1`、`1080×1080`。
5. 视频必须有声、自然男声（见 `voice.md`）。

## 素材来源与优先级

1. 用户提供的图/截图（最不容易出问题）。
2. 公开许可图库：`stock_image_search`（Wikimedia / Openverse → Pexels / Unsplash 兜底）。新闻人物优先 Wikimedia（CC BY / CC BY-SA 明确）。
3. X / 微博等社交媒体：ego-browser 抓原帖截图（注意游客态与登录态差异），只作编辑用途并标注账号。
4. 行情/官方页面截图：作为「证据图」，注明截取时间与网址。
5. AI 生成：**非必要不生成**；要用时先确认模型与费用，且不用真人形象生成。

## 署名与合规

- CC BY：署名 + 许可 + 是否修改；CC BY-SA：同样且衍生同协议；CC0/PD 最省心。
- Unsplash/Pexels：保留摄影师与平台链接（写进 `SOURCES.md` / 页面许可表）。
- 数据与引文：写明「按文中披露的当日收盘涨幅整理」这类口径，避免让人以为是官方统计。
- 不编造互动量、来源、专家意见；不确定就不写。

## 文件清单

- 页面：`article.md`、`article.v1.md`（改动前）、`annotations.json`、`<标题>.html/.pdf/-长图.png`、`assets/figs/*`、`assets/x/*`（推文原截图）。
- 卡片：`cards/index.html`、`cards/output/*.png`、`cards/assets/SOURCES.md`。
- 视频：`video/index.html`、`video/compositions/*`、`video/audio/vo.mp3`、成片 MP4、`-抖音发布文案.md`。
